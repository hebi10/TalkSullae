# LIVE-01 — Google 로그인 사용자 닉네임·기본 프로필

기준: `main` 0.4.1 / versionCode 5, Google Drive 톡술래 전체서비스기획서 v1.0, 기존 2-C Firebase 실시간 방 구조. 이 작업은 Firebase/Play 실제 배포가 아니라 코드와 자동 QA 변경입니다.

## 구현 내용

- Google 계정 인증 성공 또는 로그인 세션 복원 시 Firestore `users/{uid}` 프로필을 읽고, 없다면 닉네임·아바타 설정 화면을 요청합니다. 읽기 실패는 신규 계정으로 오판하지 않고 재시도 화면을 표시합니다.
- `saveMyProfile`(Callable, 서울 리전)로만 서버 쓰기를 허용합니다. `nickname`은 NFC 정규화 후 2~16자, `avatar`는 부엉이·토끼·고양이 중 선택합니다. 닉네임 중복은 허용하며 UID로 실제 계정을 식별합니다.
- 본인 계정의 프로필만 Firestore에서 읽을 수 있습니다. 직접 쓰기, 타인 조회, 전체 목록 조회는 거부합니다.
- 프로필 저장 시 본인이 가입한 기존 활성/승인 대기 방의 `members/{uid}.displayName`과 `avatar`를 함께 갱신하며, 이후 방 생성·가입 시 Google 표시명보다 저장된 닉네임을 우선합니다. 구버전 계정의 전환 기간에는 프로필 미생성 계정의 기존 Google 표시명 대체 경로를 유지합니다.
- 계정 삭제 작업은 사용자 프로필 문서도 삭제합니다. 삭제 진행 중 프로필 생성·갱신을 거부합니다.
- 로그인 후 `마이`에서 실제 닉네임/아바타 확인·수정 가능. 현재 메인 홈의 로컬 데모 화면 통합은 후속 LIVE-02입니다.

- 편집 화면 이탈로 지연된 저장 응답은 무효화하되 동일 계정의 진행 중인 프로필 조회 및 로딩 해제는 정상 처리합니다. 조회·저장 버전을 분리하고 단위 회귀 테스트로 확인합니다.

## 자동 검증

- 입력·권한 위조·유효성 Node 단위 테스트.
- Emulator: 프로필 생성, 과거 멤버 이름 동기화, 신규 방 가입자 닉네임 반영, 삭제 대기 중 변경 차단.
- Firestore Rules: 본인 프로필 get 성공, 비회원·타인 get, list·직접 쓰기 모두 거부.
- Android: Compose 닉네임 입력/아바타 선택/저장 화면 테스트.
- API 29/35/36 휴대폰, API 36 태블릿 기존 QA 및 OPS-07/08 배포 안전 검사 유지.

## 운영 적용 전 필수

1. 현재 **운영 Firebase**에 배포된 `Functions/Rules/Indexes`와 코드의 계약을 실측 비교하고, 별도 승인으로 필요한 변경을 안전하게 적용합니다. 운영 Firebase는 이 PR에서 변경하지 않습니다.
2. Play 설치본의 실제 Google OAuth SHA-1/SHA-256, Credential Manager 계정 선택, Firebase uid 분리 및 2계정 가입·닉네임 표시를 실기기에서 확인합니다.
3. 이전 버전의 방 멤버 이름은 저장 시 동기화되지만, 이미 저장된 과거 메시지의 작성자 이름 스냅샷은 변경하지 않습니다.
4. 가입 방 인덱스가 100개를 초과하면 함수는 원자성을 지키기 위해 변경을 거절하며 운영 검토가 필요합니다.
5. 기존 `main`을 기준으로 CI와 Codex 검토가 완료되기 전 병합하지 않습니다. Play internal/closed/production, Firebase 운영 배포, 스토어 등록정보 변경 없음.
