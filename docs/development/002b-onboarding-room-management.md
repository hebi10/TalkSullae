## 화면 및 경로

| 화면 | 구성 | 실제 지원 | 서버 기능 |
|---|---|---|---|
| S01 시작 | 첫 진입 안내, 데모 시작, 초대받은 화면 시연 | Compose 화면 탐색 | Android App Links 연결 전 |
| S02 온보딩 | 닉네임(2~16자), 3개 기본 아바타 선택, 데모 계속 | 입력 검증·로컬 상태 | Google/Kakao 로그인 미연동 |
| S03 내 방 | 목록, 빈 상태, 로딩·오프라인 상태 시연 | 로컬 목록/상태 전환 | 온라인 로딩·미읽음 동기화 없음 |
| S04 방 생성 | 이름 2~24자, 설명 최대 120자, 가입 승인 스위치 | 로컬 미리보기 방 추가 | Firestore 방 생성 미연동 |
| S05 초대·가입 | 방장 가입 승인/거절 시연, 일반 사용자 초대/대기/승인/거절/강퇴/만료 상태 | 시각적 상태 변경 | 링크 발급·카카오 공유/가입 승인 미연동 |
| S15 멤버 관리 | 멤버 목록, 방장만 강퇴·위임 메뉴, 확인 다이얼로그 | 로컬 목록 변경 | 서버 권한/강퇴·위임 없음 |

### 탐색 흐름

1. 시작 → 닉네임·아바타 → 내 방 (로그인하지 않은 데모 사용자).
2. 시작 → '초대받은 화면' → 닉네임 → 초대 시연 (실제 딥링크가 아님).
3. 내 방 → 방 생성 → 유효성 확인 → 로컬 방 추가 → 방 채팅.
4. 기존 방 → 멤버 관리, 방장일 때만 초대 버튼 표시.
5. 방장이 '강퇴/위임 시연'을 택하면 확인 다이얼로그 후 로컬 목록/방장 표시 변경.
6. 일반 멤버인 '동네 친구들'에서는 초대·강퇴·위임 화면을 제공하지 않음.

### 권한·저장에 관한 정확한 표현

- 방장/일반 멤버는 예시 로컬 데이터로 분기하며 서버에서 확인하지 않는다.
- 초대 링크·Google 로그인·실제 사용자 가입과 신고·차단·서버 멤버 자격을 처리하지 않는다.
- 화면에서 실행한 방 생성·강퇴·위임은 **현재 앱 실행 중 메모리 상태**만 수정한다. 앱을 종료하면 재설정된다.
- 방장 위임 후 현재 데모 사용자의 방장 메뉴는 즉시 숨긴다.
- S01 온보딩 데모는 매 앱 새 실행 시 다시 표시된다. 온보딩 완료 영구 저장은 인증 도입 후 연결.
- 방 초대 상태의 '승인/거절/강퇴/만료'는 실제 서버 응답이 아닌 미리보기 선택임을 표시한다.

## 검증 계획

- 단위 테스트: 방 이름 2~24자, 줄바꿈 제한, 설명 최대 120자, 방장 예시 구분, 6종 초대 상태.
- Android 계측: 시작/온보딩→방 진입/게임, 기록 탭, 유효한 방 생성, 방장 초대 상태, 강퇴 확인, 일반 멤버 권한, 빈 방 상태.
- 기존 CI: `testDebugUnitTest lintDebug assembleDebug`.
- 에뮬레이터 CI: API 35 계측 `connectedDebugAndroidTest`, 기본·200% 글꼴 홈 캡처.
- QA: 360dp/393dp/412dp, 200% 글꼴, 폴더블 확대, IME 키보드, TalkBack은 추가 검증이 필요하며 CI의 2개 홈 캡처만으로 전 화면 합격이라 판단하지 않는다.

## 기준 미확정
