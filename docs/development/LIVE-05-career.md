# LIVE-05 — 서버 검증 누적 전적·개인 프로필

- 선행 스택 LIVE-01~04, Firebase Functions 서울 리전 계약 보존.
- getMyCareer는 Firebase 인증 UID만 신뢰하며 요청 본문으로 타인 UID를 받지 않습니다.
- 본인의 userRooms/{uid}/rooms 인덱스에서 현재 가입 상태인 최대 50개 방을 조회한 후, 방이 실제 활성 상태이고 본인 멤버 자격이 활성인 경우의 playerStats/{uid} 데이터만 집계합니다.
- 50개를 초과한 방의 전적은 일부만 보여 주지 않고 명시적인 오류로 처리합니다. 게임 결과와 시즌 점수 계산 방식, 정산 원장에는 변경이 없습니다.
- Android 마이 탭은 실제 계정에서 서버 전적을 보여주고 새로고침·오류 상태를 제공하며 개발용 데모 계정에는 노출하지 않습니다.
- 노출 대상은 본인의 누적 결과뿐이며, 다른 사람의 개인정보·익명 역할은 반환하지 않습니다. 방별 월간 시즌 및 연대기는 기존 온라인 기록 탭을 사용합니다.
- Android/Firebase Emulator/Play 승인 게이트, 운영 Functions 미배포 및 실제 Google 계정 다중 기기 QA 제한 유지.


## FCM 옵트인 구현
- 사용자가 실제 Google 계정으로 로그인한 뒤 설정에서 알림을 켜야 기기 FCM 토큰이 서버에 등록됩니다. Android 13 이상은 그 시점에 POST_NOTIFICATIONS 권한을 요청합니다.
- 서버 pushTokens는 개인별 최대 3개, 클라이언트 직접 읽기/쓰기를 허용하지 않습니다. 저장된 토큰은 공개 응답이나 로그에 출력하지 않습니다. 계정 삭제 시 토큰과 발송 제한 상태도 재귀 삭제합니다.
- 서버에서 생성된 일반 채팅 메시지, 게임 PLAYING 전환, 멤버 가입 승인에 대해 **데이터 전용** FCM을 발송합니다. 메시지 본문·실제 닉네임·비밀 역할·투표 정보는 보내지 않고, 수신 Android 서비스가 Firebase Auth UID 일치와 해당 기기 알림 동의를 확인한 뒤 일반적인 문구만 표시합니다.
- 방별·사용자별·이벤트 종류별 30초 발송 제한 및 차단된 발신자의 채팅 알림 생략 정책을 적용합니다.
- 로그아웃 시 기기 푸시 등록 해제를 먼저 시도하고 실패하면 로컬 설정을 해제하며 기기 토큰 삭제를 요청합니다. 전송 실패 및 백그라운드 플랫폼 제약이 있으므로 실제 기기에서 FCM 권한/배터리/계정 전환/재설치 E2E를 별도로 검증해야 합니다.
- 운영 Firebase Functions/trigger, 실제 Google Play 설치본·알림 권한은 아직 배포·검증하지 않았습니다.

- 기기 토큰 재발급은 별도의 새 기기로 계산하지 않습니다. 난수 기반 설치 식별자의 서버 문서 한 건만 갱신하며, 사용자 변경 요청 revision이 더 높은 경우 지연된 이전 FCM 등록 요청을 서버가 무효화합니다.
- 알림 설정 화면에서 자동 갱신과 사용자 해제를 동시에 실행하지 않습니다. 기존 동의에 대한 토큰 갱신은 FirebaseMessagingService가 처리하며 동의 상태를 바꾸지 않습니다.

- 서버 발송 가능 기기 한도(최대 3대)는 `enabled=true`이면서 유효한 토큰이 있는 기기만 계산합니다. FCM이 무효화한 토큰은 동의 기록을 보존하더라도 한도에서 제외하며, 전체 기기 기록 12건 초과 시 관리 검토를 요구합니다.
