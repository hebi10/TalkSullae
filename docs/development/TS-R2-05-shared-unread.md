# TS-R2-05 읽음 이벤트 순번 이관
- 기존 Play 0.5.0(6)은 방 목록 읽음 수 필드를 사용하지 않음을 소스에서 확인. 0.6.0 후보는 legacy 인덱스 및 신규 순번 방식을 모두 표시한다.
- 기존 방은 새 메시지가 처음 성공하는 트랜잭션에서 활성 멤버의 이전 unreadCount를 carry로 보존하고 읽음 기준을 이관한다. 신규 가입/승인/재가입은 현재 순번부터 집계한다.
- 이관 후 전송은 방의 epoch/sequence/활성 송신자별 건수, 메시지 및 호출 제한 문서만 갱신(기존 수신자별 최대 20개 인덱스 쓰기 제거). 활성 멤버 조회는 기존과 동일. 방 문서의 활성 멤버에게만 보이는 카운터에는 원문·별칭·개인 역할이 없음.
- 최신 메시지 ID를 서버에서 확인한 읽음 요청만 해당 사용자 인덱스를 갱신. 90일 공백 후 epoch 변경으로 카운터 초기화. 값은 확인 이후 신규 전송 이벤트 수이며 만료/삭제되지 않은 메시지의 정확한 개수와는 다를 수 있음.
- 목록은 이관된 활성 방의 서버 확인 스냅샷을 구독. 계정/권한/캐시 불일치 시 카운터를 숨기며 레거시 방은 기존 필드 유지. 쓰기 감소와 추가 방 문서 구독의 읽기 비용·지연은 운영 전후 비교 필요.
- 이 PR은 운영 이관을 실행하지 않으며, 운영 서버와 신규 클라이언트를 함께 검증 후 적용. 이전 R2 개발 중간 빌드의 기존 인덱스 기반 표시와는 호환되지 않음.
