# LIVE-06 — 신고 운영·계정 삭제·보안/관측 검증

운영 Firebase, Google Play 변경 없이 소스/Emulator 단계에서 준비합니다.

## 운영 권한 모델
- 운영 담당자는 별도 Firebase Admin SDK 관리자 절차로 **talksullaeModerator=true** 커스텀 클레임을 가진 계정만 사용할 수 있습니다. 일반 Google 로그인, 방장 권한, 프론트엔드 입력값으로 이 권한을 만들 수 없습니다.
- getModerationInbox는 활성 검토 상태(received/under_review)의 신고를 1~30건씩 가져옵니다. 운영 증거·신고 내용·신고자 ID는 서버에서 승인된 운영 담당자에게만 제공하며, 일반 앱은 Firestore 직접 읽기 불가입니다.
- setModerationStatus는 UUID 멱등 키, 5~500자의 처리 이유와 상태 전이를 서버 트랜잭션으로 검증합니다. moderationAudit는 요청당 한 번만 create하고 재사용·완료 후 변경을 차단합니다.
- **주의:** 상태 'resolved'는 운영자가 처리 근거를 기록했다는 뜻이며, 실제 악성 채팅·계정에 대한 삭제나 제재를 자동 집행하지 않습니다. 제재 전에는 서버 권한 분리·이의제기·법정 보존 요구를 확인해야 합니다.

## 최소 관측 기준
- 2시간 간격 점검 함수는 24시간 넘게 처리되지 않은 신고와 수동 개입/재시도 실패 상태의 계정 삭제 대기 건수를 **최대 50건 한도 내에서** 집계합니다.
- 경고 로그에는 숫자·검사 상한 초과 여부만 기록합니다. 신고 텍스트·UID·게임 역할·FCM 토큰·비밀번호를 출력하지 않습니다. 별도 Cloud Monitoring 경고 정책은 운영 승인 후 구성합니다.
- Google Firebase Crashlytics/App Check 강제 적용은 기존 설치본과의 호환 검증 전까지 보류합니다. 앱 알림과 신고/삭제 경로의 QA를 필수 출시 게이트로 둡니다.

## 개인정보 보존
- 신고 증거는 운영 담당자 접근으로 제한하고 법령/정책에 따른 보존·삭제 판단을 문서화합니다.
- 앱 계정 삭제 서버 대기열은 실패·재시도·manual-review를 보존하며, 운영 담당자는 처리 상태를 모니터링합니다. 성공으로 확인되지 않은 작업을 사용자에게 삭제 완료라고 표시하지 않습니다.
- 현재 새 FCM 기기 토큰·알림 상태는 계정 삭제 시 users/{uid} 재귀 삭제에 포함합니다. 과거 채팅 expiresAt 이전 데이터 정리는 별도 적법한 마이그레이션 전까지 자동 삭제 성공으로 간주하지 않습니다.

## 릴리스/병합 게이트
LIVE-01~05 스택의 Android API 29/35/36·태블릿, Firebase Emulator 보안·운영자 권한, OPS-08 수동 승인 안전 검사, 최신 Codex P1/P2 0건 후 별도 병합합니다. 실제 운영 Firebase·관리자 권한 발급·FCM 실기기·Google Play 내부/비공개 배포는 미수행입니다.

- 운영 큐는 문서 ID를 기준으로 안정적으로 정렬하며 limit+1을 조회해 nextCursor/hasMore를 반환합니다. 다음 페이지는 afterId를 넘겨 이어서 조회합니다. 진행 중인 신고도 계속 목록·지연 점검에 남습니다.
- 일반 안전 신고의 roomReference 역시 운영자 전용 응답에 포함해 신고자가 제공한 조사 참고 정보를 보존합니다.
